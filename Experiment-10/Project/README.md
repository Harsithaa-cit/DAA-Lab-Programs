# Experiment 10 – Improving Quick Sort Efficiency using Randomized Algorithm

## Aim

To implement and compare Deterministic Quick Sort and Randomized Quick Sort in Python and analyze their performance on different input configurations.

## Problem Statement

Implement both Deterministic Quick Sort, using the last element as the pivot, and Randomized Quick Sort, using a randomly selected pivot. Compare their performance based on execution time and number of comparisons for arrays of size 10,000.

## Input Configurations

The algorithms are tested on four different types of input:

1. Random array
2. Sorted array
3. Reverse-sorted array
4. Nearly-sorted array

## Algorithms

### Deterministic Quick Sort

The last element of the current sub-array is always selected as the pivot.

* Average Case: O(n log n)
* Worst Case: O(n²)

### Randomized Quick Sort

A random element is selected as the pivot and moved to the last position before partitioning.

* Expected Case: O(n log n)
* Worst Case: O(n²)

Random pivot selection reduces the possibility of consistently choosing a poor pivot because of the input arrangement.

## Pseudocode

### Deterministic Quick Sort

```text
DETERMINISTIC_QUICKSORT(arr, low, high)

    IF low < high

        pivot_idx ← PARTITION(arr, low, high)

        DETERMINISTIC_QUICKSORT(arr, low, pivot_idx - 1)

        DETERMINISTIC_QUICKSORT(arr, pivot_idx + 1, high)
```

### Randomized Quick Sort

```text
RANDOMIZED_QUICKSORT(arr, low, high)

    IF low < high

        rand_idx ← RANDOM(low, high)

        SWAP(arr[rand_idx], arr[high])

        pivot_idx ← PARTITION(arr, low, high)

        RANDOMIZED_QUICKSORT(arr, low, pivot_idx - 1)

        RANDOMIZED_QUICKSORT(arr, pivot_idx + 1, high)
```

### Partition

```text
PARTITION(arr, low, high)

    pivot ← arr[high]

    i ← low - 1

    FOR j ← low TO high - 1

        IF arr[j] ≤ pivot

            i ← i + 1

            SWAP(arr[i], arr[j])

    SWAP(arr[i + 1], arr[high])

    RETURN i + 1
```

## Expected Observation

For random input, both algorithms generally show similar performance because the input does not consistently produce poor pivot choices.

For sorted and reverse-sorted inputs, Deterministic Quick Sort with the last element as the pivot reaches its worst-case behavior of O(n²). For an array of 10,000 elements, this results in approximately:

```text
49,995,000 comparisons
```

Randomized Quick Sort avoids this predictable behavior in expectation by selecting the pivot randomly and generally maintains O(n log n) performance.

Nearly-sorted input can also expose the weakness of a fixed pivot strategy, while randomized pivot selection provides more robust performance.

## Result

The experiment demonstrates that Deterministic Quick Sort is highly sensitive to input ordering when the last element is always selected as the pivot. Randomized Quick Sort provides more robust expected performance by randomly selecting the pivot.

Therefore, Randomized Quick Sort is more suitable when the input distribution is unknown or may contain unfavorable arrangements.

## Conclusion

Deterministic Quick Sort can degrade to O(n²) when the pivot selection repeatedly produces highly unbalanced partitions. Randomized Quick Sort reduces the likelihood of such unfavorable partitions and provides expected O(n log n) performance across different input configurations.

The experimental and web-based comparisons demonstrate the practical efficiency advantage of randomized pivot selection.
